> 机制卡 · 多结局/选择结构/游戏叙事

## 核心要旨

多结局不是多写几段不同剧情，而是先立起两三个贯穿全篇的变量——禁忌、嘱托、立场或关系选择——最后让每个结局成为这些变量的不同取值组合。结局不是随机岔路，而是一组前面选择的结算表。

## 这个机制解决什么问题

很多分支故事的坏结局像突然踩中陷阱，好结局则像作者奖励玩家。变量式设计能让结局“服理”：玩家回头看，发现早期听不听劝、是否牵住某人的手、把忠诚交给谁，都已经在结局里兑现。

## 结构步骤

1. **先定主题，再选变量**：变量必须表达主题，不能只是钥匙颜色或隐藏数值。
2. **控制在 2–4 个变量**：每个变量都要能用一个动作或立场说清楚。
3. **第一幕展示变量的安全版本**：让玩家先在低风险场景做一次选择。
4. **中段重复变量并提高代价**：同一个选择第二次出现时，失去的东西更多。
5. **让变量彼此冲突**：如果所有变量都能同时满足，结局没有重量。
6. **建立结局矩阵**：列出每种组合，不要只凭灵感写结局。
7. **让惩罚与选择同形**：看了不该看的失去眼睛，放弃同行者的人最终独自离开。
8. **至少设计一个“成功但悲剧”的结局**：让玩家知道达成目标不等于没有代价。

## 具体写法示范：三结局短篇《守门人》

### 先定两个变量

- **变量 A：是否打开门**
	- 0 = 遵守母亲遗言，不开门。
	- 1 = 为了见失踪的姐姐，打开门。
- **变量 B：是否说出真名**
	- 0 = 只称呼门后之物为“姐姐”。
	- 1 = 说出姐姐生前的全名。

这两个变量不是装饰：打开门代表“愿意接近过去”，说出真名代表“承认眼前的东西已经不是原来的人”。

### 第一幕：低风险预演

主角在家里发现一扇小时候不能开的储物门。母亲遗言是：“听见里面叫你，不要开；如果非要回答，不要叫它的名字。”

这一幕只让玩家选择是否把手放上门把，不立刻产生严重后果。选择本身先进入变量记录。

### 第二幕：提高代价

夜里门后传来姐姐小时候唱过的歌。主角如果不打开门，能在门缝下看到姐姐的旧发卡；如果打开门，门后没有姐姐，只有一条通往地下室的楼梯。

此时不立刻惩罚玩家，而是给不同信息：遵守禁忌得到安全但失去主动，打开门得到路线但进入危险。

### 第三幕：让变量冲突

地下室里，姐姐的声音要求主角叫出全名。旁边墙上写着：“名字一旦被说出，门就知道你是谁。”

主角必须决定：想确认姐姐身份，就要承担让门认出自己的风险。

### 结局矩阵

| A 是否开门 | B 是否说真名 | 结局 |
|---|---|---|
| 否 | 否 | 主角活着离开，但姐姐永远只能作为一个未确认的声音存在 |
| 是 | 否 | 主角见到姐姐的影子，但无法确认她是否仍是本人；门继续留在家中 |
| 是 | 是 | 门获得主角身份，姐姐被释放，主角成为下一任守门人 |
| 否 | 是 | 不应出现的组合可作为隐藏结局：主角在门外喊出真名，门从屋内转移到主角体内 |

### 结尾回收

第一幕母亲说“不要叫它的名字”，结尾不能只写成提示语，而要具体兑现：喊出真名的人不一定立即死亡，但从此所有人叫的都是“门里的主角”。身份被夺走，比死亡更贴合变量的代价。

## 示例作品

- **《零：红蝶》**：牵手/放手、是否回头或目视禁忌、究竟替村子还是眼前的人完成仪式，共同形成不同结局。
- **《尼尔》系列**：牺牲同伴、删除数据等选择在不同周目中互相注释，结局不是单次道德评分。
- **《极乐迪斯科》**：立场、思维和供述方式共同影响同一案件的意义。
- **文字冒险作品**：早期“不要告诉某人”“不要进入某处”的嘱托，在坏结局与真结局分别兑现。

## 常见错误

- 变量只在结尾揭晓，玩家无法理解为什么进了坏结局。
- 变量太多，结局变成条件计算而不是故事。
- 所有变量都是“好/坏”，没有互相冲突的价值选择。
- 真结局把之前的代价全部抹掉，导致普通结局显得没有意义。
